# 编码与修改约定

## 通用原则

- 优先修复明确问题，保持 diff 小而聚焦。
- 新代码先说明所属层级，避免页面继续承担算法、解析和存储等所有职责。
- 不复制文件后保留 `copy`、`final`、`finial`、`test1` 等含义不明的命名。
- 删除旧实现前先确认引用关系，并保留可运行的替代路径。
- 注释解释原因和边界，不复述代码字面含义。

## Vue 与 uni-app

- 新页面和重构组件优先使用 Vue 3 Composition API；未触及的旧代码不要求一次性改写。
- 组件通过明确的 props 和事件通信，跨页面共享数据走统一状态，不直接操作其他页面实例。
- 生命周期使用 Vue 3 语义，并同时确认 uni-app 页面生命周期。
- 新界面使用统一图标，不继续用表情符号充当正式图标。
- 样式考虑不同屏幕、安全区域和滚动容器，避免依赖固定列表高度。
- 平台条件编译集中在适配层，不散落到核心业务逻辑。

## TypeScript 与数据

- TypeScript 渐进引入，优先覆盖账户模型、TOTP 参数和二维码解析结果。
- 类型定义以真实数据为准，不为了通过检查而使用无依据的 `any` 或断言。
- 账户标识稳定唯一；时间相关字段使用明确单位。
- 持久化结构变更必须考虑旧数据迁移，不能直接让用户账户消失。

## 测试与提交

- 纯逻辑测试不依赖 UI、真机时钟或网络。
- 算法测试使用公开标准向量和确定性输入，不只打印结果，必须有断言。
- 解析测试覆盖参数乱序、URL 编码、缺失参数、非法 Base32 和不支持的算法组合。
- 每次提交只包含一个逻辑主题，不混入无关格式化或环境产物。
- 完成说明必须列出修改文件、验证命令或人工验证步骤，以及未验证风险。
