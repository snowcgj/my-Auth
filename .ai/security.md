# 安全约束

这些规则适用于所有功能开发、调试、重构和文档示例。

## 密钥与日志

- 不记录完整 `secret`、账户对象、二维码原文、备份内容或验证码。
- 调试日志使用不含敏感信息的账户 ID、阶段和错误类型。
- 仓库和文档只使用公开演示密钥；真实密钥一旦提交，应立即轮换并清理历史。
- 未经用户明确确认，不新增账户数据上传、远程同步或第三方分析能力。

## 存储与备份

- 不把 `uni.setStorageSync` 等同于安全密钥存储；当前代码没有应用层加密。
- 密钥保护方案需要考虑 Android Keystore、iOS Keychain 等系统能力，以及不支持平台的降级边界。
- 备份和导出默认必须加密，并说明密码遗忘、数据损坏和版本兼容的处理方式。
- 不做明文云同步，不把应用锁当作密钥加密本身。

## 输入与平台权限

- `otpauth` 解析必须按参数名读取并正确 URL 解码，不依赖参数顺序。
- Base32 只忽略明确允许的格式字符；空密钥、非法字符和不支持的参数必须报错。
- 当前 TOTP 支持 SHA1/SHA256/SHA512、6/8 位、30/60 秒；HOTP、未知算法或不支持的位数/周期必须拒绝，不能静默按默认参数处理。新增 SHA2 的用户真机反馈见对应计划。
- 从相册识别仅处理用户选择的图片，不上传内容、不新增存储权限；只清理由本次操作创建的确切缓存文件，不删除原图。系统选图与备份必须共享原生回调互斥，避免挂起已有请求。
- Android 和其他平台权限遵循最小必要原则，新增权限必须说明用途。
- 使用剪贴板时提供明确反馈，并评估自动清除和后台快照保护。

## 密码学实现

- 当前 HMAC-SHA1 是 TOTP 标准默认算法，不因 SHA-1 碰撞问题而盲目替换。
- 手写算法改动必须通过 RFC 6238 标准向量，并与成熟实现进行对照。
- 不自行发明加密备份格式或口令派生方案；选用成熟算法和库前先评估跨端兼容性。
