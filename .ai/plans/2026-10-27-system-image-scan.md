## 技术选择

- 首页添加面板新增“从相册识别”，空状态也有入口。API 33+ 尝试 Photo Picker，启动失败及 API 19–32 使用 ACTION_OPEN_DOCUMENT(image/*)。保留相机扫码。
- 新增平台层统一 Activity 结果入口，备份 2001/2002 与选图 3001 共享原生选择器互斥；只安装一次监听，未知结果转交原有可调用处理器。不并发启动多个系统选择器，不引入每个页面单独覆盖的回调链。
- content URI 通过 ContentResolver 打开，复制到本次创建的应用缓存文件；使用 Java Channels + ByteBuffer 分块复制，避免每字节跨桥接和 JS byte[] 参数问题。验证每次 read/write 的数字返回值、文件长度，20MiB 上限；不转 URI 为公共文件路径，不新增存储权限。
- 复制后交 plus.barcode.scan（仅 QR），完成/失败/取消后尝试删除本次临时文件。原图不修改；页面卸载令牌失效后不添加账户。取消选择静默，读取失败/识别失败/非 TOTP 分开反馈。
- 不假定 Photo Picker URI 必须在回调栈内同步读完。保留原生返回的读取授权，失败时报告，不申请持久读取授权。
- manifest 显式包含 Barcode 模块；不扩展现有权限。模块配置/最终 App 打包需另验。

## 验证与边界

- Node 模拟桥接测试结果路由、互斥、取消、启动异常恢复、分块复制/部分写入/大小限制/无进展或 undefined 返回、关闭与临时文件清理、识别失败和卸载取消。
- 备份文件读写通过统一入口回归；既有逐字节写入/验证算法保留。新测试加入 npm test。
- Android 必验：原生 UI、PNG/JPEG 截图识别、普通无二维码图片、取消后重试、权限/不支持格式失败、大图耗时、选择器启动兼容、选图后备份导出/恢复和反向顺序。
- 模拟桥接不是 Native.js/设备验证；ByteBuffer 桥接、私有缓存绝对路径和原生引擎对 HEIF 等格式仍待真机。不把异步包装称作后台 IO，复制阶段仍可能阻塞 JS。
- 不提交或推送，不删除既有文件/目录。只清理由本次操作创建的确切临时文件，进程异常退出时可能残留于系统缓存。

## 实施与验证结果

- 首页两项添加入口，空状态也支持图片；共用 BusyOverlay 增加 icon prop。识别成功后重读账户，再复用 parseQRCode/persistAccounts；重读失败保留原数据，不按空数组覆盖。
- 新增 activity-result.js 与 platform-image.js；备份只迁移结果获取/错误收尾，已验证写入/读回算法未改，读上限检查修正为允许恰好 1MiB。
- Photo Picker 启动异常回退系统文件选择器；系统取消不自动再开另一个选择器。临时文件只在读取阶段创建，成功/失败/卸载取消都清理该文件；系统回调永不返回与进程终止仍是边界，不虚报已取消原生操作。
- 全量 npm test 112/112，约 91 秒；平台新增 16 项，覆盖路由互斥/转交、启动失败重试、部分写入、undefined/无进展返回、空/非图/超大、关闭/清理、解码失败/取消、选图之后的备份写入验证和读取。
- 12 个 Vue SFC 检查通过；DOM 模拟容器 36 项检查通过，覆盖双入口、等待层、取消、SHA512 图片结果接解析、无二维码提示、读取失败保留账户、卸载后不写入。该容器模拟图片平台函数；不能作为 Native.js/相机/原生选择器证据。
